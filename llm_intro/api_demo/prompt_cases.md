# Prompt 案例集（prompt_cases.md）

本文件汇总大模型 API 调用中常见的 Prompt 设计案例，覆盖基础调用、结构化输出、角色设定、多轮对话、Prompt 模板管理等场景。每个案例包含**场景说明**、**Prompt 设计思路**和**示例 Prompt 文本**，可直接复用或改造。

---

## 一、基础调用案例

### 案例 1：事实问答

**场景说明**：用户提出一个明确的事实性问题，期望得到准确、简洁的答案。

**设计思路**：

- 用 system 设定角色，限定回答风格。
- user 直接提问，避免含糊。
- Temperature 设低（0.0-0.2），保证确定性。

**示例 Prompt**：

```text
system: 你是一位知识渊博的助手，回答要准确、简洁，不确定时明确说"我不确定"。

user: 珠穆朗玛峰的海拔是多少米？
```

**预期输出**：直接给出海拔数值，不编造，不废话。

---

### 案例 2：文本摘要

**场景说明**：将长文本压缩为简短摘要，保留核心信息。

**设计思路**：

- system 限定摘要长度和风格。
- user 提供待摘要文本，并指定输出要求。
- Temperature 设中等（0.3-0.5），兼顾准确和流畅。

**示例 Prompt**：

```text
system: 你是一位专业的文本摘要助手，擅长提炼核心信息，输出简洁明了。

user: 请将以下文章摘要为 3 句话，保留关键数据和时间节点：

[粘贴文章内容]
```

**预期输出**：3 句话概括全文，包含关键数据和事件。

## 二、结构化输出案例

### 案例 3：信息抽取（JSON 格式）

**场景说明**：从非结构化文本中抽取结构化信息，便于程序解析。

**设计思路**：

- system 明确要求输出 JSON。
- 提供 Schema 或示例，减少格式错误。
- Temperature 设 0.0，保证输出稳定。
- 强烈建议启用 JSON Mode 或 Function Calling。

**示例 Prompt**：

```text
system: 你是一位信息抽取助手，只输出 JSON，不要输出其他内容。
输出格式：{"姓名": "", "公司": "", "职位": ""}

user: 请从以下文本中抽取人物信息：

"张三最近加入了阿里巴巴，担任高级算法工程师。"
```

**预期输出**：

```json
{"姓名": "张三", "公司": "阿里巴巴", "职位": "高级算法工程师"}
```

---

### 案例 4：情感分析（带置信度）

**场景说明**：对文本做情感极性判断，并给出置信度和关键词。

**设计思路**：

- 定义明确的输出字段。
- 要求置信度为 0-1 的浮点数。
- 要求列出支撑判断的关键词。

**示例 Prompt**：

```text
system: 你是一位情感分析专家，只输出 JSON。
输出格式：{"情感极性": "正面/负面/中性", "置信度": 0.0-1.0, "关键词": ["", ""]}

user: 请分析以下评论的情感：

"这部电影的画面很美，但剧情太拖沓了，看到一半就想睡觉。"
```

**预期输出**：

```json
{"情感极性": "负面", "置信度": 0.72, "关键词": ["剧情拖沓", "想睡觉"]}
```

---

### 案例 5：文本分类（多标签）

**场景说明**：为文本打上多个类别标签。

**设计思路**：

- 提供候选标签集合，避免模型自创标签。
- 要求输出标签列表，按相关性排序。
- Temperature 设 0.0。

**示例 Prompt**：

```text
system: 你是一位文本分类助手，只输出 JSON。
候选标签：["科技", "财经", "体育", "娱乐", "政治", "社会"]
输出格式：{"标签": ["", ""]}

user: 请为以下新闻打标签：

"苹果公司今日发布了新款 iPhone，搭载 A17 Pro 芯片，售价 7999 元起。"
```

**预期输出**：

```json
{"标签": ["科技", "财经"]}
```

## 三、角色设定案例

### 案例 6：专业角色扮演

**场景说明**：让模型以特定专业身份回答，提升回答的专业性和针对性。

**设计思路**：

- system 中明确角色、知识范围、回答风格。
- 限定回答格式（如分点、带示例）。
- 可加入"不知道就说不知道"的约束。

**示例 Prompt**：

```text
system: 你是一位有 10 年经验的 Python 后端工程师，擅长 Django、FastAPI 和数据库优化。
回答要求：
1. 先给出结论，再解释原因。
2. 涉及代码时，用简洁的伪代码或关键片段说明。
3. 不确定的技术细节要明确说明，不要编造。

user: 如何优化 Django ORM 的 N+1 查询问题？
```

**预期输出**：先给出结论（用 select_related / prefetch_related），再解释原理和使用场景。

---

### 案例 7：教学助手

**场景说明**：让模型以教师身份，用通俗语言解释复杂概念。

**设计思路**：

- 限定受众（如"面向高中生"）。
- 要求用类比和例子。
- 控制篇幅，避免长篇大论。

**示例 Prompt**：

```text
system: 你是一位善于用类比讲解复杂概念的物理老师，面向高中生。
回答要求：
1. 先用一句话概括核心。
2. 再用一个生活类比帮助理解。
3. 最后补充一个常见误区。

user: 什么是"熵"？
```

**预期输出**：一句话概括 + 生活类比（如房间混乱度）+ 常见误区（熵不是"混乱"本身）。

## 四、多轮对话案例

### 案例 8：客服对话

**场景说明**：模拟多轮客服对话，模型需要记住上下文。

**设计思路**：

- system 设定客服角色和服务规范。
- 每轮对话携带完整历史。
- 限定回复语气（礼貌、简洁）。

**示例 Messages 结构**：

```text
system: 你是一位友好的电商客服，回答要礼貌、简洁，不确定时引导用户联系人工客服。

user: 我的订单什么时候到？
assistant: 您的订单预计明天送达，请问还有其他可以帮您的吗？
user: 能帮我查下具体几点吗？
assistant: 预计下午 3 点左右送达，具体以快递员通知为准。
user: 好的，谢谢。
```

**预期输出**：礼貌收尾，如"不客气，祝您购物愉快！"。

---

### 案例 9：代码调试对话

**场景说明**：用户提供错误代码，模型逐步引导排查。

**设计思路**：

- system 设定调试助手角色。
- 要求先复述问题，再给排查步骤。
- 鼓励用户提供更多信息。

**示例 Prompt**：

```text
system: 你是一位耐心的代码调试助手。
回答要求：
1. 先复述你理解的错误现象。
2. 给出 2-3 个最可能的排查方向。
3. 询问用户能否提供更多信息（如完整报错、环境版本）。

user: 我的 PyTorch 训练时 loss 一直是 nan，怎么办？
```

**预期输出**：复述问题 + 排查方向（学习率过大、数据含 nan、梯度爆炸）+ 追问信息。

## 五、Prompt 模板管理案例

### 案例 10：翻译模板

**场景说明**：多语言互译，需要复用和变量替换。

**设计思路**：

- 固定指令 + 变量占位符。
- 明确源语言和目标语言。
- 保留专业术语。

**模板文本**：

```text
system: 你是一位专业翻译，精通 {{source_lang}} 和 {{target_lang}}。
翻译要求：
1. 保持原文语气和风格。
2. 专业术语保留原文并括号注释。
3. 只输出译文，不要解释。

user: 请将以下 {{source_lang}} 翻译为 {{target_lang}}：

{{source_text}}
```

**变量**：`{{source_lang}}`、`{{target_lang}}`、`{{source_text}}`

---

### 案例 11：摘要模板

**场景说明**：长文档摘要，可控制长度和侧重点。

**模板文本**：

```text
system: 你是一位文本摘要助手。
摘要要求：
1. 长度控制在 {{max_length}} 字以内。
2. 重点保留 {{focus}} 相关内容。
3. 用 {{style}} 风格输出。

user: 请摘要以下文档：

{{document}}
```

**变量**：`{{max_length}}`、`{{focus}}`、`{{style}}`、`{{document}}`

---

### 案例 12：代码生成模板

**场景说明**：根据需求生成代码，可指定语言和框架。

**模板文本**：

```text
system: 你是一位 {{language}} 开发专家，熟悉 {{framework}}。
代码要求：
1. 代码要可运行，包含必要的导入。
2. 关键逻辑加注释。
3. 输出格式：先给完整代码，再简要说明思路。

user: 请实现以下需求：

{{requirement}}
```

**变量**：`{{language}}`、`{{framework}}`、`{{requirement}}`

## 六、进阶技巧案例

### 案例 13：Chain-of-Thought（思维链）

**场景说明**：需要多步推理的数学或逻辑题。

**设计思路**：

- 要求模型"一步一步思考"。
- 先输出推理过程，再给最终答案。
- Temperature 设 0.0-0.3。

**示例 Prompt**：

```text
system: 你是一位数学老师，解题时要一步一步推导，最后给出答案。

user: 一个水池，进水管 3 小时注满，出水管 5 小时排空，同时打开，几小时注满？
请一步步思考。
```

**预期输出**：分步推导（效率计算 → 净效率 → 时间），最后给出 7.5 小时。

---

### 案例 14：Few-shot 示例

**场景说明**：通过少量示例让模型理解任务格式。

**设计思路**：

- 在 Prompt 中提供 2-3 个输入输出示例。
- 示例要覆盖典型情况。
- 最后给出待处理的输入。

**示例 Prompt**：

```text
system: 你是一位文本分类助手，只输出类别标签。

user: 请根据示例，判断以下评论的情感类别。

示例 1：
输入："这家餐厅太好吃了！"
输出：正面

示例 2：
输入："服务态度很差，再也不来了。"
输出：负面

示例 3：
输入："味道一般，价格偏贵。"
输出：负面

现在请判断：
输入："环境不错，但菜品分量太少了。"
输出：
```

**预期输出**：负面（因为"分量太少"是负面评价）。

---

### 案例 15：约束输出格式

**场景说明**：需要严格控制输出格式，便于后续解析。

**设计思路**：

- 明确指定分隔符或结构。
- 要求不输出多余内容。
- 可配合正则校验。

**示例 Prompt**：

```text
system: 你是一位信息抽取助手。
输出格式必须严格为：字段名|字段值，每行一个字段，不要输出其他内容。

user: 请从以下文本中抽取信息：

"李四，28 岁，居住在北京，是一名软件工程师。"

输出格式示例：
姓名|张三
年龄|30
城市|上海
职业|工程师
```

**预期输出**：

```text
姓名|李四
年龄|28
城市|北京
职业|软件工程师
```

## 七、Prompt 设计检查清单

在正式使用 Prompt 前，建议逐项检查：

```text
✅ 角色是否明确？（system 是否设定了身份）
✅ 任务是否清晰？（user 是否说清楚了要做什么）
✅ 输出格式是否指定？（JSON / 列表 / 段落）
✅ 是否提供了示例？（Few-shot 能显著提升稳定性）
✅ 是否设定了边界？（不知道就说不知道，不要编造）
✅ Temperature 是否合适？（事实问答低，创意写作高）
✅ Max Tokens 是否足够？（避免答案被截断）
✅ 是否做了异常处理？（非 JSON 输出时的容错）
✅ 模板变量是否清晰？（{{variable}} 命名规范）
✅ 是否记录了实验日志？（输入、输出、参数值）
```

## 八、常见错误与改进

| 常见错误 | 问题 | 改进 |
| :--- | :--- | :--- |
| Prompt 太模糊 | "帮我写点东西" | 明确任务、受众、长度、格式 |
| 未指定输出格式 | 模型输出自由文本 | 要求 JSON 或固定结构 |
| 未设角色 | 回答风格不稳定 | system 设定专业身份 |
| Temperature 过高 | 事实问答出现幻觉 | 降到 0.0-0.2 |
| 未给示例 | 模型理解偏差 | 加入 2-3 个 Few-shot 示例 |
| 无边界约束 | 模型编造信息 | 加"不确定就说不知道" |
| 变量未命名 | 模板无法复用 | 用 {{variable}} 占位符 |
| 无异常处理 | 解析失败程序崩溃 | 加 try-catch 和重试 |
